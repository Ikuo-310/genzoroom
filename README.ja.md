# GenzoRoom

[English](README.md) | 日本語

GenzoRoom（現像室）は、写真管理アプリ Immich と連携する、セルフホスト型の写真現像Webアプリです。

Immichでは扱いが難しいJPEGとRAWのペアを自動検出してスタック化するほか、手動でのスタックの組み換えや代表写真（カバー）の変更にも対応しています。

また、JPEG写真の色や明るさを調整する非破壊現像機能を搭載。現像した写真は元画像を残したままImmichに書き戻し、元画像と自動的にスタック化して、新しい写真をカバーに設定します。  
写真の管理はImmichが担当し、GenzoRoomが写真の原本を直接編集・削除することはありません。  
Immichとの連携に特化しているため、外部からの写真の取り込みや、ローカルへのファイル書き出し機能は搭載していません。

ユーザーインターフェースは日本語と英語に対応しています。その他の言語への翻訳協力も歓迎しています。

現在はJPEG現像のみ対応していますが、将来的にはRAW現像への対応も予定しています。

## 現在の機能

### Immichの閲覧とAnshitsu

- 以下に記載する、確認後のSTACK管理書き込みを除き、バックエンド経由で認証付きのImmich写真アクセスを行います。
- Homeには6つのタブがあります：Recent、Albums、Calendar、Favorites、Stacks (STACK管理)、Export (出力管理)。4つの閲覧タブと2つの管理タブの間には視覚的な間隔があります。右端に独立して配置された「暗室へ」ボタンから、別のAnshitsuワークスペースを開きます。
- Homeはコンパクトなダークヘッダー、タブ、ツールバー、コンテンツ領域で構成されます。コンテンツをスクロールしてもヘッダー、タブ、ツールバーは固定されます。中立的なダークテーマはSTACK管理と共通です。デスクトップ向けのレイアウトは、幅が狭い場合にも適応します。
- Homeの写真一覧にはImmichのゴミ箱にあるアセットは表示されません。Recent、Favorites、Albums、Calendarの日付別結果では、Immich Stackはプライマリ/Cover写真で表され、子アセットは別カードとして表示されません。不正または曖昧なStackメタデータはHomeから隔離され、1件の不正なStackスナップショットによって写真一覧全体が失敗することはありません。AlbumsにはArchiveアセットを含め、既存のImmichアルバム表示動作が適用されます。
- Stackカードにはメンバー数とStack内の一意な画像形式が表示され、Coverの形式が先頭に表示されます（例：JPEG、DNG、HEIC）。形式バッジをクリックすると、その形式に該当するすべてのアセットをAnshitsuの対象にするかどうかを切り替えられます。HomeとExportのカードで長いファイル名を表示する際は、中間部分を省略し、幅が限られている場合も拡張子と末尾の識別に役立つ部分を表示します。
- Recent、Albums、Calendar、FavoritesでStackのCoverカードをAnshitsuで開くと、複数のStackアセットを送れます。最初の選択では、未ExportのNon-RAWアセットをすべて選択します。該当アセットがない場合は、未ExportのRAWアセットをすべて選択します。GenzoRoomタグが付いたアセットはStack候補から除外されます。コンテキストメニューの上段ではアセットを個別に選択でき、下段では編集済みアセットをExport Queueへ追加または削除できます。項目をチェックしてもAnshitsuへ移動しません。手動選択はブラウザーセッション中、4つのタブ間で共有されます。単独アセットではブラウザー標準のコンテキストメニューを維持します。また、Galleryカードが選択されていない状態で`D`を押しても、前回のAnshitsuセッションを再開します。RAWアセットはAnshitsuで表示できますが、RAW現像は実装されていません。
- RecentにはImmich Timelineの画像が降順で表示されます。50～500枚の範囲を50枚刻みで選択できます（初期値は100枚）。Archiveアセットは除外されます。
- AlbumsにはImmichのアルバムが一覧表示され、各アルバムを共通の写真グリッドで開けます。アルバムの表示可否には既存のImmichアルバム動作が適用されます。
- Calendarでは年、月、日付詳細の各ビューを利用できます。月のセルには代表サムネイルが表示され、Timeline画像がある日付だけが有効になります。Archiveのみ、または動画のみの日付は写真のある日として扱われません。月表示と日付詳細には同じImmich Timelineのローカル日付境界を使用するため、UTC日付をまたぐタイムゾーンオフセットがあっても、月のセルと異なる日付詳細に写真が表示されることはありません。
- Calendarでは、修飾キーを押さずにLeft / Right矢印を押すと、月、年、または（日付詳細の場合）写真のある前日/翌日へ移動します。日付移動では写真のない日を飛ばします。
- Favoritesにはお気に入りに設定されたTimeline画像が表示され、Homeがマウントされている間は読み込みに成功した一覧を再利用します。
- 写真グリッドではRAW / Non-RAW、編集済み / 未編集のフィルターを利用できます。各フィルターはHomeのタブごとに独立しており、2つのフィルターは組み合わせて適用されます。
- Recent、Album、Calendarの写真ビューでは、Stackに属するアセットと属さないアセットをフィルターできます。Stackカードはメンバー数のメタデータを保持し、既知のメンバー全体の編集状態を集約します。Favoritesでも同じHomeのプライマリのみのデータ境界を使用しますが、既存のフィルター動作は維持されます。
- 共通コントローラーでHomeグリッドのサムネイルサイズを選択できます。Numpad `-` / `+`でサイズを小さく/大きくできます。ショートカット説明が有効な場合、ボタンのツールチップにもこのヒントが表示されます。
- Immichの`GenzoRoom`タグが付いた写真には、Homeで「現」バッジが表示されます。一致するGenzoRoom書き出し済みJPEGからタグがなくなっている場合、Homeはファイル名と埋め込みJPEG識別情報を確認した後、通知を表示せずにタグを復元します。
- Recent、Favorites、Album詳細、Calendarの日付詳細には、順序付き選択ツールバーがあります。Album一覧とCalendarの月/年ビューには写真の選択操作がありません。Select Allは現在表示されている写真を追加し、非表示の選択項目は保持します。選択順序も保持されます。
- 写真カードを通常クリックするとその写真だけを選択します。`Primary`+クリックでは選択を切り替え、`Shift`+クリックではアンカーから両端を含む範囲を追加します。アンカーがない状態で最初にShift+クリックしても何も起きません。チェックボックスでは選択を切り替え、Shift+クリックでは範囲を追加します。ClearまたはEscapeで選択を解除します。Anshitsuを開くには`D`または選択ツールバーを使います。
- Homeのショートカットは`R` Recent、`A` Albums、`C` Calendar、`F` Favorites、`E` Export、`S` STACK管理、`D` Anshitsuです。Homeのタブはクリックまたはこれらの直接コマンドで切り替えます。Left / Right / Home / Endではタブを切り替えません。任意で表示できるサフィックスは`[R]`、`[A]`、`[C]`、`[F]`、`[E]`、`[S]`、`[D]`です。`Primary+A`はサフィックスとして表示されません。Settingsでは、コマンドを無効にせずにサフィックスとショートカット説明を非表示にできます。`Primary+A`は写真ビューで表示中のすべての写真、Exportで変更可能なQueueカードをすべて選択します（Windows/LinuxではCtrl+A、macOSでは⌘A）。ネイティブ編集、Album一覧、Calendarの年/月ビューでは通常の動作を維持します。
- `S`は常にSTACK管理タブを開きます。Galleryビューから入る際、空でない選択があれば、そのAsset IDの集合に対応するセッションを開始または再開します。選択がなければ前回のセッションを再開し、初回は空の状態を表示します。Export管理からSTACK管理に戻る場合は、保持されているStackセッションを再開します。Galleryから`D`または「暗室へ」を使うとAnshitsuが開き、選択がなければ前回のAnshitsuセッションが存在する場合に再開します。STACK管理中はボタンと`D`が無効になります。
- AnshitsuまたはSTACK管理から戻ると、Homeは閲覧タブ、詳細ビュー、スクロール位置を復元します。タブ間の移動中も各Homeビューのスクロール位置を記憶します。
- Filmstripでアクティブな写真を切り替えられます。現在の写真のEXIF詳細も表示されます。
- Filmstrip写真の一時除外には、写真の左上にある×ボタン、またはアクティブな写真で`X`を使います。最後に残った写真は除外できません。アクティブな写真を除外すると次の写真へ移動し、最後の写真の場合は前の写真へ移動します。他の写真を除外した場合は現在の表示を維持します。`Primary+Z`では直近の除外を元の位置に復元します。アクティブだった写真を復元するとその写真を表示し、非アクティブだった写真を復元すると現在の表示を維持します。この1回限りのUndoは、次の編集、手動での写真切り替え、除外、Galleryへの復帰で失効します。写真、Recipe、Historyは保持されます。除外は現在のAnshitsuセッションに限られ、再入場時にリセットされます。
- ショートカットの修飾キー表示はプラットフォームに従います。Windows/LinuxではCtrl、Alt、Shift、macOSではCommand (⌘)、Option (⌥)、Shift (⇧)を使います。
- `G`でAnshitsuからGallery/Homeへ戻ります。Anshitsuでは`F`でViewerフォーカスモードを切り替え、`Shift+Z`（macOSでは`⇧+Z`と表示）でFitと直前のzoom/panを切り替えます。`Primary+Shift+←/→`（macOSでは⌘+⇧と表示）でFilmstripの写真を切り替えます。
- HomeとFilmstripでは引き続きImmichサムネイルを使います。AnshitsuはImmichプレビューで開始し、選択中のJPEGオリジナルだけをバックグラウンドで取得します。JPEGのみの撮影データとPixel `RAW-01.COVER.jpg`にも同じ経路を使います。その写真が選択されたままの間はオリジナルを再利用し、選択を離れると解放します。取得またはデコードに失敗しても、プレビューで編集できます。Immich API認証情報はバックエンドに保持されます。
- Before / Afterの横でPreviewとOriginalを切り替えられます。どちらの表示モードも、Recipe、History、Undo / Redo、調整のON/OFF状態を共有します。表示モードの選択は一時的で、保存されません。OriginalはBefore / After、Fit、1:1、Histogramでも使用できます。Previewの表示中も、Original Infoには埋め込みカラープロファイルの説明と画像寸法が表示されます。
- Viewerのショートカット：`]`でPreview / Originalを切り替え、Backslashを押し続けると一時的にBeforeを表示します。`Shift+Z`でFitと直前のzoom/panを切り替えます。JISキーボードでは、`]`がイベントコード`Backslash`より優先されます。オリジナルの読み込み中または利用できない間、このキーでBackslashの動作は実行されません。既存のテキスト入力、IME、ダイアログ、メニューのガードも引き続き有効です。
- ViewerツールバーではBefore / Afterより前にPreview / Originalを配置します。左側のHistoryパネルと右側のDevelopパネルのボタンには、状態に応じた矢印アイコンと日本語・英語のツールチップを使用します。
- 写真を開くと、SQLiteから写真ごとのJPEG編集RecipeとHistoryが復元されます。Filmstripで変更済みの写真を切り替える前に保存されます。
- 変更済みのJPEG編集は、編集操作から5秒間変更がないと自動保存されます。Filmstripで切り替える場合は引き続き即時保存されます。
- AnshitsuからHomeへ戻ると、そのAnshitsuセッション中に編集したすべての写真を保存し、各Historyを圧縮します。
- 保存済み編集のある写真には、HomeグリッドとFilmstripで編集済みマーカーが表示されます。Homeでは、表示中の写真順に沿ったShift+クリック範囲選択を利用できます。
- 共通のGenzoRoomタイトルを押すと、既存の保存・終了フローを通じてAnshitsuからHomeへ戻ります。HomeのタイトルはHomeに留まります。
- Undo / Redo（`Primary+Z`、`Primary+Shift+Z`、`Primary+Y`）、個別調整のReset、カテゴリのReset、All Reset。
- Historyの行を選ぶと、その編集状態へ直接移動できます。ヘッダーと行の右クリックメニューから、Historyの圧縮、消去、選択行からの部分削除、編集の初期化を行えます。圧縮、消去、部分削除は直後にUndoできます。消去とリセットにはローカライズされたCancel / Continue確認があり、取り消せない操作である旨の警告はリセットの場合のみ表示されます。
- 写真間で調整値をコピーして貼り付けられます。`Primary+C`では現在のスライダー操作対象をコピーし、Viewerが対象の場合はすべての値をコピーします。`Primary+V`ではスライダーやViewerにフォーカスする必要なく、コピーした値をアクティブな写真に適用します。`Primary+Alternate+C`と`Primary+Alternate+V`では項目選択ダイアログを開きます。Viewerの`⋯`メニューからも4つすべての操作を利用できます。
- Copy / Pasteでは、16個すべての数値調整に対してタブ内共通のGenzoRoomクリップボードを1つ使います。有効/無効フラグはコピーされません。タブ内でHomeへ移動して戻ってもクリップボードは保持され、ページ再読み込みまたはタブを閉じると消去されます。OSのクリップボード内容は使用しません。
- JPEGプレビューと選択中のオリジナルの描画にはWeb Workerと任意のWebGPUを使用します。保留される編集は常に最新のものだけです。Workerを利用できない場合や失敗した場合はメインスレッドへフォールバックします。
- Fit、1:1、zoom、panのコントロール。
- Before / After表示の切り替えと、Backslashキーを押し続けて一時的にBeforeを表示する機能。比較表示では編集やzoom/panを変更せずにDevelop調整を迂回します。
- JPEGプレビューと選択中のオリジナルから8-bit sRGB Histogramを生成します。R、G、B、Y′それぞれに256個のビンがあります。Scopeでは、少なくとも1つのチャンネルを表示したままRGBを個別に表示/非表示にできます。また、Y Only、RGB共通の最大値を基準にしたNormalスケール、nearest-rank P99を使うExpandedスケールを利用できます。Viewerの固定または一時的なBefore / After表示の両方に追従します。デスクトップでは右パネルに対する高さを15%～40%の範囲で変更でき（初期値は30%）、設定はブラウザーに記憶されます。
- Histogramショートカット：Numpad 0でY Onlyを切り替え、Numpad 1、2、3でR、G、Bを切り替えます。Numpad DecimalでNormal / Expandedを切り替えます。Y Onlyが有効なとき、最初のNumpad 1～3入力では前のRGB選択を復元し、次の入力でそのチャンネルを切り替えます。テキストフィールドと数値フィールドでは通常のテンキー入力を維持します。
- Anshitsuで写真を切り替えても、RGB表示、Y Only、スケールモードの選択は保持されます。
- デスクトップのサイドバーは個別に折りたたみ/サイズ変更ができ、幅を記憶します。
- HomeとAnshitsuから共通のSettingsダイアログを利用できます。表示言語はAuto、日本語、英語から選べます。Autoはブラウザーの優先言語に従い、該当がなければ英語を使います。日付・時刻のロケールは表示言語とは独立しており、Autoではブラウザーの地域設定を使います。日本、米国、英国、その他の対応地域を選択できます。Calendarの週の開始曜日はAuto、Sunday、Mondayから選べます。キーボードショートカット表示設定では、TooltipsとMenusのショートカット説明を制御します。説明をオフにしてもショートカットは有効です。
- WebGPUの有効化やAnshitsuの初期画像選択（Auto、Original preferred、Preview preferred）など、画像関連の設定はブラウザーに保存されます。AutoではWebGPUが有効かつ利用可能な場合はオリジナルを優先し、それ以外ではプレビューを維持します。選択中のJPEGオリジナルの読み込み中はプレビューを表示し、Preview優先またはユーザーが表示元を手動選択した場合を除き、読み込み完了後に自動で切り替えます。
- SettingsにはGenzoRoomとバックエンドの接続状態に加えて、Immichサーバーのバージョンと利用可能なビルド情報が表示されます。設定はブラウザーに保存され、Immich APIキーはバックエンドに保持されます。

### Export管理

- Homeタブまたは`E`でExport / 出力管理を開きます。Galleryのビュー状態を保ったまま、同じHeader / Tabs / Toolbar / Contentシェルを使用します。
- 永続化されたExport Queueは、個別の写真カードとして表示されます。同じImmich Stackに属するQueueアセットが2つ以上ある場合はグループ化され、Queueに入っているメンバーだけが表示されます。グループは最初のQueueメンバーから始まり、メンバー順を維持します。メンバーが1つだけになると単独カードになります。サムネイルサイズはHomeと共通です。
- Exportカードには現在、Queueアセットを識別するためにImmichのソースサムネイルが表示されます。GenzoRoomのRecipeで描画したプレビューではありません。
- 通常クリック、Primary+クリック、Shift+クリック、チェックボックス、Select All / `Primary+A`でカードを選択します。Shift範囲は表示されたグループ順に沿います。ClearとEscapeで選択を解除します。
- `W`を押すと、選択された変更可能なカードを明示的にExport待機状態にします。状態が混在する選択では待機をONにし、すべて待機中の場合はOFFにします。選択解除やHomeタブの切り替え後も待機状態を維持しますが、一時的な状態であり、再読み込み後には保存されません。永続的なQueueメンバーシップやRuntime状態`waiting`とは別の状態です。
- 待機中のカードでは、サムネイル下端に幅いっぱいで高さ28pxのステータスバーを重ねて**Ready to export / 出力待機中**と表示します。
- 失敗したExportの再試行中は、失敗したカードだけを操作できます。他のQueueカードは内部の待機状態を保持しますが、待機バッジは一時的に非表示となり、選択と削除が無効になります。この制限はタブバーに表示されます。失敗項目のない状態でRetryが終わると、通常の操作に戻ります。
- `Q`またはRemove from Queueでは、選択された`queued` / `failed`アセットを順次削除します。削除に成功したアセットはすぐに消えます。失敗した場合も成功済みの処理は保持し、ローカライズされたアラートとともに一覧を更新します。`waiting`、`encoding`、`registering`のカードは選択、待機状態変更、削除がロックされます。GalleryとAnshitsuでは、各画面固有のQueue切り替え動作を維持します。
- Exportで`Primary+Z`（Ctrl+Z / ⌘Z）を押すと、直近のWによる待機状態変更またはQによる削除を1回Undoできます。選択は復元されず、Redoもありません。
- **Export to Immich / Immichへ出力**で確認すると、待機中の`queued`アセットをQueue順に、保存済みRecipeを使用して開始します。出力はフル解像度JPEGで、ファイル名は系列に基づく`GenzoNN`形式です。GenzoRoomタグを付け、元StackのCoverに設定します。Exportのキャンセルを確認すると、現在の写真の処理後に停止します。失敗項目がある場合、**Retry export / 出力を再試行**で確認すると、それらの項目だけを最新の保存済みRecipeで開始します。開始、キャンセル、Retry、成功したExportはW/Q Undoの対象外です。
- Backend再起動後は、中断された処理が再開します。登録が途中で止まるとアップロード済みアセットが残ることがあり、まれに出力が重複する可能性があります。

### STACK管理

- STACK管理は通常のHomeタブです。RAWアセットやFavoritesからの選択も含め、順序付きのHome選択をエディターへ送れます。編集開始前に既存のImmich Stackを完全なメンバー構成とともに解決します。Galleryで選択がない場合は前回の編集セッションを再開し、初回は空の状態を表示します。順序に関係なく同じAsset ID集合なら下書きを維持し、空でない別の集合なら新しいセッションを開始します。タブの切り替えやAnshitsuへの移動後も、現在のSPAセッション中は未送信編集とUndoを保持します。
- エディターでは常にSTACK候補が上、未分類写真が下となる2つの独立スクロール領域を表示します。初期の高さ比率は2:1です。仕切りをドラッグして上部領域を50%～80%（1:1～4:1）の範囲で設定できます。この比率はHomeセッション中に維持され、再読み込み後は2:1に戻ります。下部領域全体にStackメンバーをドロップするとそのメンバーを削除します。写真カードへのドロップでは既存のカード操作を使います。
- 対応するPixel RAWやMotion Photoの命名パターンを含め、ファイル名の系列が完全一致するかでRAW / JPEG候補を検出します。名前が異なる場合、TIME、カメラのメーカー/モデル、GPSのEXIF情報がすべて一致し、RAW 1件とNon-RAW 1件の組み合わせが一意なら候補として提案します。
- 変更されていない自動候補にはNAME / TIME / CAM / GPSの根拠を表示します。既存のImmichグループにはIMMICH表示が残り（変更時は黄色）、手動グループとメンバー変更のある自動グループにはMANUALを表示します。ワークスペースはCOVERを自動選択し、変更もできます。
- 未分類写真をStackに追加したり、グループまたはメンバーをPurgeしたり、手動Stackを作成したりできます。デスクトップのDrag & Dropで未分類写真をStackへ移動する、Stack間でメンバーを移動する、メンバーを未分類に戻す操作もできます。未分類写真を別の写真にドロップすると2メンバーのMANUAL Stackが作られます。未分類領域の空白にドロップしても何も起きません。グループを元のImmichメンバー構成とCOVERに戻すと、元のStackの系譜が復元されます。
- `Primary+Z`で、D&Dにより作成した手動Stackを含め、直近のローカルStack構造編集を1回Undoできます。UndoではImmichのソースデータを巻き戻したり結果を送信したりしません。RedoとUndoボタンはありません。
- 既存StackのCOVER以外かつ非RAWのメンバーを右クリックし、**Move to trash / ゴミ箱に入れる**を選ぶとゴミ箱移動を予約できます。サムネイルにはゴミ箱アイコンが表示されます。現在のCOVERとImmichから最初に読み込んだCOVERは保護されます。新規追加または移動してきた写真は対象外です。**Cancel trash reservation / ゴミ箱予約を取り消す**を選ぶか、送信前なら同じ1回限りの`Primary+Z` Undoで取り消せます。
- 予約はStack編集とともに**Send to Immich / Immichへ送信**で適用されます。写真は完全削除されず、Immichの通常のゴミ箱へ移動します。**Purge**はStackの下書きから写真を削除するだけでImmichには残ります。ゴミ箱への移動とは異なる操作です。Stackに予約がある間は、COVER変更、Purge、メンバー移動の前に予約を取り消してください。未分類写真の追加は引き続き可能です。
- 送信を確認すると、最終下書きを変更なし、作成、更新、削除に分類します。変更のないStackは書き込みを行いません。Coverのみの変更ではプライマリを更新します。Immich v3.2.4でメンバーを変更する場合は、旧Stackを解除して置き換えを作成します。一部だけ成功した場合は結果を表示します。不確かな結果があると、盲目的な再試行を防止し、再検出が必要になります。
- Stackカードの長いファイル名表示には、Galleryと共通の中間省略を使用します。Immich送信ボタンにはExportと同じ赤いアクションスタイルを使用します。
- このワークスペースはデスクトップブラウザー向けです。タッチ操作のDrag & Drop、Stack/グループの並べ替え、外部ファイルのドロップには対応していません。
- メンバーが1つのImmich Stackは異常なStackとして表示され、Homeには赤い`1`バッジ、STACK管理には警告が表示されます。通常のStackとして編集できず、グループのPurgeのみ可能です。この操作には既存の確認付き削除プランが適用されます。変更されていない単独メンバーStackは書き込み操作を発生させません。
- 送信する操作がある場合に限り、ツールバーに保留中の作成 / 更新 / 削除件数を表示します。操作がない状態で送信すると、変更がないことを報告します。

### Developer Diagnostics

- オプトインのDeveloper Diagnostics Logsタブでは、FrontendとBackendの個別レベル、消去とJSON書き出しの操作、更新、統合/ソース別ビューを利用できます。Frontendのログは同一オリジンのタブ間で同期されます。Developer Diagnosticsを閉じると、両方の収集機能が停止します。既定ではログ記録はオフです。診断イベントには[`AGENTS.md`](AGENTS.md)に記載されたプライバシー境界が適用されます。

### JPEG編集状態と保存

AnshitsuはDevelop操作を有効にする前に、保存済みのJPEG編集状態を読み込みます。変更済み編集は操作がない状態が5秒続くと、History全体とともに自動保存されます。Filmstripを切り替える前にも、変更済み写真を保存します。**Back to photos**では、Anshitsuセッション中に編集した各写真を順番に最終保存し、それぞれのHistoryを圧縮します。保存応答が失われた場合、GenzoRoomは新しいスナップショットを送信する前に、同じスナップショット、revision、save IDで再試行します。実際のrevision競合はマージせずに報告されます。デバウンス中または保存処理中にブラウザーを再読み込み/終了すると、最新の編集が失われる可能性があります。Browser Backとタブ終了の捕捉は実装されていません。最後の保存に失敗した場合は、Anshitsuに留まるか、保存せずに終了するかを選べます。

### 現在の調整項目

編集できるのは現在JPEGアセットのみです。AnshitsuはImmichが生成したJPEGプレビューで開始し、選択中のJPEGオリジナルを画像ソースとして使うこともできます。

| カテゴリ | 調整項目 |
| --- | --- |
| White Balance | Temperature, Tint |
| Basic | Exposure, Contrast, Highlights, Whites, Shadows, Blacks |
| Color | Vibrance, Saturation |
| Color Grading | Shadows Temperature, Shadows Tint, Midtones Temperature, Midtones Tint, Highlights Temperature, Highlights Tint |

Recipe v18では、16個の数値調整それぞれに個別のON/OFFスイッチがあり、カテゴリとColor Gradingの範囲にも独立したスイッチがあります。この23個のスイッチは互いの有効/無効を切り替えず、スイッチをオフにしても数値は保持されます。個別、カテゴリ、範囲、すべてのリセット操作はHistoryとUndo / Redoの対象です。処理はブラウザー内で行われ、Immichのオリジナルは変更されません。

### 任意のWebGPU高速化

AnshitsuではWebGPUを使い、JPEGプレビューと選択中のオリジナルに対する調整を高速化できます。WebGPUのON/OFFスイッチはSettingsにあり、設定はブラウザーに記憶されます。Settingsでは保存済みの設定と実際の処理状態を区別して表示します。互換性のあるGPU、ドライバー、ブラウザーが必要です。WebGPUには通常Secure Contextが必要です。一般的な利用ではHTTPSを推奨します。WebGPUを利用できない場合、またはGPUの初期化/描画に失敗した場合、AnshitsuはCPU Workerを使います。Workerも失敗した場合は既存のメインスレッド処理へフォールバックします。WebGPUがなくても編集できます。

Windows上のFirefoxとEdge、およびRadeon RX 580の組み合わせで動作を確認しています。RX 580は最低要件ではありません。HTTPで提供されるLANアドレスでは、ブラウザー固有の開発用例外でオリジンをセキュアとして扱う場合に限り、WebGPUを使えるブラウザーがあります。この例外で接続が暗号化されることはなく、HTTP通信は暗号化されません。一般的な利用ではHTTPSを推奨します。ブラウザーごとの詳細な例外設定手順は、このガイドの対象外です。

Copy / Pasteでは、無効なカテゴリ、調整項目、Color Grading範囲の値も含め、保存済みの数値をコピーします。ON/OFFスイッチはコピーされません。貼り付けではコピーした調整値だけを変更し、貼り付け先写真の有効フラグを維持します。カテゴリ、個別調整、Color Grading範囲のコンテキストメニューには、それぞれ該当するコピー、貼り付け、リセット、切り替え操作があります。選択したPasteでは、クリップボードを変えずに任意の一部を適用できます。変更があった貼り付けは、コピー元のファイル名をラベルとする1件のUndo可能なHistoryとして表示されます。既にある値を再度貼り付けても新しい項目は作成されません。テキスト/数値入力欄ではブラウザー標準のCopy / Paste動作を維持します。

## 現在の制限事項

- 作業用画像とHistogramのパイプラインは、引き続きブラウザー管理の8-bit sRGBです。オリジナルのデコード時に埋め込みsRGBおよびDisplay P3プロファイルを考慮し、この作業色空間に変換します。広色域またはHDRのパイプラインではありません。
- HEIC、PNG、RAWなど、JPEG以外のアセットは編集できません。
- DNGを含むRAW現像は未実装です。STACK管理ではJPEGとRAWの撮影データをグループ化できますが、編集できるのはJPEGのみです。JPEGの`COVER.jpg`はJPEGオリジナル経路で処理します。
- オリジナルの描画ではフル解像度のピクセルを処理します。対応環境ではWebGPUで高速化できます。CPU処理も引き続き利用できますが、検証済みのNAS / Firefox環境では低速です。詳細な性能ベンチマークは実施していません。
- 5秒のデバウンス中または保存処理中に行った編集は、再読み込みやタブ終了で失われる可能性があります。これらのブラウザーイベントは捕捉されません。
- Recentには選択した50～500件の範囲が表示されます。現在、ページネーションと検索はありません。
- Anshitsuはデスクトップを優先しており、モバイル専用の編集ワークスペースはありません。
- STACK管理はデスクトップブラウザーで利用できます。タッチ操作のDrag & DropとStack/グループの並べ替えには対応していません。

## 未実装

- GenzoRoom Export以外で再インポートされたアセットをImmich Stackへ自動的に追加する機能。
- Drag & DropによるStack/グループの並べ替え。
- STACK管理でのタッチ操作によるDrag & Drop。
- Color GradingのPoint / Widthコントロール。現在、3つのトーン範囲には固定ウェイトを使用します。
- Waveform Monitor (WFM)、RGB Parade、Vectorscope。HistogramはScope領域に実装されています。
- マスキングまたは部分調整。
- Cropまたは回転ツール。
- AI支援による調整。
- ノイズ除去。

これらは現在の対応範囲を示すものであり、リリースの約束や確定したロードマップではありません。

## セキュリティとデータの取り扱い

- 通常の写真アクセスにはImmichの読み取りエンドポイントを使用します。専用APIキーには`user.read`、`asset.read`、`asset.view`、`asset.download`、`album.read`、`tag.read`、`asset.upload`、`tag.create`、`tag.asset`、`asset.delete`、`stack.read`、`stack.create`、`stack.update`、`stack.delete`が必要です。これらはHome閲覧、JPEGオリジナル取得、Exportのアップロード/タグ付け、タグ修復、確認後のStack書き込み、確認後のImmichゴミ箱への移動（`force: false`）をカバーします。STACK管理はアセットを完全削除せず、画像オリジナルも変更しません。`server.about`は任意で、Settingsおよび診断出力にImmichのバージョン/ビルド情報を表示するために使います。
- Immich APIキーは環境変数を通じてバックエンドに渡します。フロントエンドへ送られることも、フロントエンドイメージに埋め込まれることもありません。
- ブラウザーからのリクエストには同一オリジンの`/api/`ルートを使います。提供するCompose設定では、バックエンドのポートをホストに公開しません。
- HTTPSのImmich URLでは、TLS証明書の検証を引き続き有効にします。上流のレスポンス本文、認証情報、内部例外の詳細はブラウザーに公開しません。
- 提供するコンテナは非rootユーザーで動作し、Linux capabilitiesを削除して権限昇格を無効にします。
- GenzoRoomは画像オリジナルを変更しません。SQLiteの編集状態APIが保存するのはGenzoRoomのRecipeとHistoryのみです。Stackメンバーシップの書き込みは、明示的に確認されたSTACK管理操作に限定されます。

実際のAPIキーをコミットしたり、コンテナイメージに埋め込んだりしないでください。設定とネットワークの選択肢については[導入ガイド](docs/deployment.md)を参照してください。

## 必要条件

- Docker Compose v2を備えたDocker Engine、またはDocker Standalone環境に接続したPortainer。
- 現在GHCR配布イメージで動作確認済みのLinux `amd64` Dockerホスト。Arm64はサポート対象として案内していません。
- GenzoRoomのバックエンドコンテナから接続できる既存のImmichサーバー。
- 「[セキュリティとデータの取り扱い](#セキュリティとデータの取り扱い)」に記載した権限を持つ専用Immich APIキー。`server.about`は任意です。
- GenzoRoomフロントエンドに接続できるブラウザー。ホストポートの初期値は`3190`で、`GENZOROOM_PORT`で変更できます。

正式版GHCRイメージには固定の`vMAJOR.MINOR.PATCH`タグを使用し、`latest`は最新の正式版を指します。変更可能な`alpha`タグは検証ビルド用であり、正式版ではありません。配布Composeでは公開済みイメージタグの明示が必要で、`latest`を暗黙に選択しません。正式なGitタグをPushすると、イメージ検査の成功後、そのバージョンの確定済みCHANGELOG節から公開GitHub Releaseを作成します。[導入ガイド](docs/deployment.md)と[リリース検証ノート](docs/release-validation.md)を参照してください。

## クイックスタート

GenzoRoomは単一のGHCRイメージとして配布されます。通常の利用者はソースコードのチェックアウト、Node.js、Pythonを用意する必要はありません。配布版が対応するのはLinux `amd64`です。リポジトリのReleasesまたはパッケージページで公開済みと表示されているタグだけを使用してください。このドキュメントの更新によって`v0.1.0`が公開されるわけではないため、選択前に公開済みであることを確認してください。

1. 上記に記載した必要権限を持つ専用Immich APIキーを作成します。`server.about`は任意です。
2. このリポジトリから[`compose.release.yml`](compose.release.yml)と[`.env.example`](.env.example)をダウンロードします。`GENZOROOM_IMAGE_TAG`には公開済みの固定バージョンタグを、`GENZOROOM_PERSIST_ROOT`には事前に作成したホスト側の親ディレクトリを設定します。`IMMICH_URL` / `IMMICH_API_KEY`も設定します。UID/GID `10001:10001`に、その親ディレクトリへの書き込み/通過権限を付与してください。SQLiteはそのディレクトリ配下の`data/genzoroom.db`に保持されます。LAN/HTTPS接続と同一ホスト上のImmichへの接続方法は[導入ガイド](docs/deployment.md)を参照してください。
3. Docker Composeで設定を検証し、公開済みイメージを起動します。

   ```sh
   docker compose -f compose.release.yml config --quiet
   docker compose -f compose.release.yml pull
   docker compose -f compose.release.yml up -d
   ```

   Portainerでは**Web editor**を使い、`compose.release.yml`全体を貼り付けて、Stackの環境設定に同じ変数を設定します。同一Dockerホスト上のImmichを使う場合は、導入ガイドに記載された単独Composeの例を使用してください。
4. 設定したアドレスを開きます。利用できる場合はHTTPSを使用してください。ホストポートの初期値は`3190`です。通常のHTTPでは接続は暗号化されません。
