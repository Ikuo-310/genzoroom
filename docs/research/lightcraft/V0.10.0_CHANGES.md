# LightCraft v0.10.0 差分調査記録

調査・収録日：2026-10-21（Asia/Tokyo）。対象：GenzoRoom Windows版でのRAW現像エンジン利用。

## 1. 現在の開発方針

### 開発方針の決定

今回の差分調査後に決定した方針を記録する。これはソース調査で確認した事実と区別する。

- **LightCraft v0.10.0を新しい統合開発基準として採用する。** 基準commitは`a2a41383c4fd62fa85a46ccd00998639221f2d3c`。v0.9.1は過去の検証基準・PoC実績として保持する。この方針決定後に実施したRelease buildとRX 580 DX12実機PoCは[GPU_POC_V0.10.0.md](GPU_POC_V0.10.0.md)に記録する。
- **v0.9.1との厳密な現像画像比較は行わない。** RAWプロファイルや現像アルゴリズムの変更に伴う画像差は許容し、開発段階では過去のRAW編集結果との互換性を保証しない。必要に応じて過去の編集結果を破棄して再現像する。
- 新バージョン導入時は、RAWの読込・現像、プレビュー・Export、設定の保存・復元、明らかな画質異常や動作不良の有無を基本動作として確認する。
- **LightCraftを交換可能なエンジンとして統合する。** GenzoRoomとの間にAdapter層を設け、当面は常駐MCP方式を第一候補とする。必要に応じてSession＋StageCacheを使うRust Adapterへ移行できる構造にし、CPU／GPU方式の変更をできるだけ暗室UIから分離する。常駐MCPの正式採用は未決定。
- **RX 580を前提とするWindowsネイティブGPU対応は別途調査する。** 後続の実機PoCでDX12利用を確認した。実測と限界は[GPU_POC_V0.10.0.md](GPU_POC_V0.10.0.md)を参照。

### 調査で確認したこと

ソース差分上、既存の主要接続方式を変更する阻害要因は確認しなかった。一方、設定JSON、特定RAWの色、XMP解釈、Exportのチャンネル構成には変更がある。これらの実装差分は確認済みだが、ビルド・実機動作は未検証である。今後の基本動作確認ではv0.9.1との厳密な画素一致を合格条件にしない。

## 3. MCP・CLI・Engine API・Session・StageCache

| 対象 | 判定 | 根拠・影響 |
|---|---|---|
| MCP | 変更なし（版表示を除く） | `crates/mcp`全体に差分なし。`src/server.rs`の`Server::request()`、`src/progress.rs`の`serve_stdio()`、`src/headless.rs`の`Headless::render()`／`export()`を維持 |
| CLI | 変更なし（版表示を除く） | `apps/lightcraft-cli`に差分なし。`src/main.rs`の`render()`／`run()`とMCP起動経路を維持 |
| 描画用Engine API | 変更なし | `crates/engine/src/media.rs`に差分なし。`Session::render_job()`／`preview_job()`／`accept()`、`RenderJob::draft()`／`with_stages()`／`run()`を維持 |
| Session | 変更あり・追加 | `crates/engine/src/lib.rs`の`Session`に`last_merge: BTreeMap<String, Value>`追加。`Session::new()`で初期化。`library.rs`でprefs保存・復元に追加 |
| StageCache | 変更なし | `crates/pipeline`全体に差分なし。`src/lib.rs`の`StageCache`、`clear()`、`render_cached()`を維持 |

MCPのtool名・引数・stdio方式に直接の変更はない。ただしEngineを通じた設定適用やExportの意味は後述の変更を受ける。MCP初期化応答の`serverInfo.version`とCLIの版表示はworkspace versionにより0.10.0となる。

StageCache付きPreview、Draft品質指定、実行中現像の細粒度キャンセル、細かなメモリ制御が新たにMCPへ追加されたわけではない。最新要求への集約・古い結果の破棄は引き続き呼出側／Adapterの設計課題である。

Engine全体が無変更という意味ではない。`crates/engine/src/print/compose.rs`の公開型`PageStyle`にはフィールド追加があるため、完全な構造体リテラルを使うRust利用側には修正が必要となり得る。`cmd/print.rs::specs()`の`print.set`にはページ番号などの任意設定が追加。`cmd/manage.rs::rename_args()`は`photo.rename`／`photo.renamePreview`の過大な`start`をエラーにする。

## 4. DevelopSettingsとProcess Version

### 部分JSON設定の範囲補正：変更あり

`crates/develop/src/lib.rs`の`DevelopSettings::merged()`が新設`keep_in_range()`を呼ぶようになった。

- control specを通じてスライダー値を範囲内へ補正する。追加テストでは極端なExposureを5.0、Geometry scaleの0を50.0へ補正。
- ポイントカーブの座標を0..1へ補正する。
- 回転角0のcropを画像範囲へ切り詰める。回転したcropは同じ切り詰めをしない。
- 面積のないcropは変更前の矩形へ戻し、変更前も空なら全画像範囲にする。

`develop.merge`、CLIの`render --settings`、presetなど`merged()`経由の設定適用に影響する。`crates/develop/src/presets.rs::apply_partial()`も共通補正へ集約された。従来と同じJSONを送信しても、適用後の値や描画が変わる場合がある。

`from_json()`やRust構造体の直接生成すべてに補正が追加されたわけではない。WBのtemp／tint指定でscaleを省略するとLegacyになる既存動作は維持される。

**設計提案：** GenzoRoomで入力JSONをそのまま確定設定とせず、適用後の`develop.get`で実際の値を取得・保存する。WBはcontrol APIを優先し、JSONならscaleも保持する。これは今回実装していない。

### 設定構造・Process Version：変更なし

根拠：`crates/develop/src/settings.rs`の`DevelopSettings`／`ProcessVersion`／`Process`、`crates/engine/src/cmd/develop.rs`の`develop.updateProcess`、`cmd/query.rs`の`develop.get`に差分なし。

- `SCHEMA_VERSION = 1`と描画processは別概念。
- ProcessはV1・V2、新規設定は最新V2、保存データで欠落・不正値ならV1。
- V1は通常の保存JSONでは省略されるが、`develop.get`はprocessを明示する。
- 将来のprocess番号は値を保持し、その版で理解する最新processへフォールバックして描画する。
- 更新時に既存写真のprocessを自動更新する必要は確認していない。

**方針との関係：** process固定だけではエンジン版間の画素一致を保証しない。RAW色情報やXMP変換も変わり得るため、開発段階では旧版の現像画素・編集結果との互換性を保証しない。設定全体・明示的process・エンジンcommitを保存し、必要なら旧編集結果を破棄して再現像する。未知JSONフィールドの完全な往復保持も保証しない。

## 5. XMP・RAW・CPU現像・Export

### XMP：変更あり

| 根拠ソース・関数 | 確認した変更と影響 |
|---|---|
| `crates/engine/src/crs_masks.rs::component()` | 輝度範囲マスクが白まで全強度の場合、白より明るい領域も含むよう修正。再インポート時のハイライトへの効果が変わり得る |
| 同`unmapped_local()`／`masks()` | `LocalGrain`など未対応で非中立のローカル調整を未対応項目として報告。描画対応の追加ではない |
| `crates/meta/src/xmp.rs::parse_xmp()` | ISOの0・負値を無視し、有効な代替ISOを採用。緯度±90度・経度±180度を外れるGPSを破棄 |
| 同`write_xmp_lc()`／`xml_safe()` | XML 1.0禁止文字を出力から除去。該当文字の完全往復は変わる |

XMP経由のGenzoRoom交換・バックアップ案は候補のままであり、相互運用を今回検証していない。

### RAWデコード：変更あり

- `crates/raw/src/lib.rs::decode_with()`と新規`vendor/hasselblad.rs::decode()`／`original_header_color()`／`adopt_matrices()`：Hasselblad FFFの外側に色行列がない場合、埋め込み元3FRヘッダーから採用。WBは外側の値を保持する。
- `vendor/hasselblad.rs::rgb_preview()`と`preview.rs::preview_covering()`：Hasselblad 3FR／FFFの非圧縮8-bit RGB画像をTIFF形式のpreviewとして返す経路を追加。`crates/engine/src/files.rs::decode_raw_preview()`もJPEG判定を先頭バイトに変更。
- `crates/raw/src/spectral.rs::find()`：Fujifilm X-T30／X-T30 II／X-Pro3／X100V／X-S10／X-E4にX-T3の分光行列を参照する対応を追加。
- `crates/raw/src/spectral_table.rs::ALIASES`：Canon EOS R6 Mark IIの別名対応を追加。該当機種で出発点となる色が変わり得る。
- `crates/tiff/src/image.rs::ImageInfo::chunks()`、`crates/raw/src/sparse.rs::Ranges::extend()`／`tiff_plan()`：strip長推定とヘッダー読込み計画を効率化。

### CPU現像：中核変更なし、入力・周辺の変更あり

`crates/pipeline`全体、`crates/raw/src/dng.rs`・`color.rs`、`crates/engine/src/media.rs`に差分なし。ただし設定補正、XMP変換、RAW色情報が変わればCPU出力も変わる。

既存PoCのPixel／Pentax DNGの専用デコーダやDNG色変換に直接の変更は確認しなかった。既存JPEGとのSHA-256・画素一致、時間、メモリは未確認であり、「出力変更なし」とは判定しない。

### Export：変更あり

`crates/engine/src/export.rs::encode_with_metadata()`は、不透明な8-bit PNG／TIFF／WebPをRGBAではなくRGBとして符号化する。実際の透明度は保持する。常に4チャンネルを前提にする読込みやファイルhash比較に影響する。

JPEG・16-bit Exportの符号化経路に直接の変更はない。ただし現像やXMPメタデータ由来の差は別に生じ得る。Previewと最終Exportの画素一致も今回測定していない。

headless Exportのサイズ省略時長辺3000px、原寸出力時に`longEdge: 0`を明示する既存設計は維持する。根拠：変更のない`crates/mcp/src/headless.rs::Headless::export()`。

### その他の関連変更

- `crates/codecs/src/tiff_codec.rs::limits()`：大きなstrip／tileを扱えるよう中間バッファ上限を引上げ。
- `crates/codecs/src/jxl.rs::open()`：寸法確認と追跡対象メモリ予算を導入。全割当を制限する保証ではない。
- `crates/heif/src/lib.rs`の`Coded`読込み処理：符号化寸法とgrid合計の制限を追加。従来受理した入力がエラーになる可能性がある。
- `crates/denoise-core/src/run.rs::MAX_PIXELS`：AI denoiseの上限を1億から1.1億画素へ拡大。通常の非AI現像とは区別する。
- `crates/fetch/src/http.rs::lookup()`／`connect_any()`：モデル取得時のDNS待ちtimeout・cancelを改善。
- `Cargo.toml`：workspace versionを0.10.0へ変更。Rust baselineは1.90のまま。`Cargo.lock`の既存外部依存の更新はなく、codecsのnativeテスト用`dhat`追加あり。

| 項目 | 判断・残存事項 |
|---|---|
| Adapter層 | LightCraftを交換可能なエンジンとして扱う方針を決定。GenzoRoomとの実装接続は未検証 |
| 常駐headless MCP | 当面の第一候補。正式採用は未決定。通信実接続・対話性能は未検証 |
| Rust Adapter | 必要に応じSession・StageCache・RenderJobを利用する方式へ移行できる構造とする。API利用側の再ビルドは未確認 |
| 設定保存 | merge後の確定値取得を考慮。設定全体・process・commitを保持する案を維持 |
| 画像読込み | Exportを常時RGBAと仮定していないか、採用段階で確認する |
| キャッシュ | エンジンcommitを含む管理を推奨。版間の再利用で旧結果が残ることを避ける |
| process更新 | エンジン更新と既存写真のprocess更新を別判断とする |
| CPU／GPUと暗室UI | 処理方式の変更をできるだけ暗室UIから分離する。実装状況は未確認 |
| Windows GPU | 後続実機PoCでRX 580のDX12 adapterを常駐MCPから利用し、GPU段階ログと原寸JPEG Exportの短縮を確認。詳細は[GPU_POC_V0.10.0.md](GPU_POC_V0.10.0.md)。GenzoRoom暗室UIの応答性・Rust Adapterとの比較は未確認 |

開発方針としてAdapter層を設けること、常駐MCPを当面の第一候補とすることを決定した。Rust Adapterへ移行可能な境界を保ち、CPU／GPUの選択を暗室UIから分離する。GenzoRoom実装との具体的な適合・変更量とMCPの正式採用は未確認・未決定である。

## 7. 残存課題

差分調査の収録時点では未実施だったv0.10.0のRelease buildとRX 580 DX12実機PoCは、その後完了した。常駐MCPからのRAW読込、Preview、設定変更・同一プロセス内復元、原寸JPEG Export、正常終了、およびGPU段階ログを確認している。条件と測定上の制約は[GPU_POC_V0.10.0.md](GPU_POC_V0.10.0.md)に記録した。

今後の確認項目：

1. GenzoRoom Python Backendから常駐MCPへ実接続し、RAW読込、設定取得・変更、Preview取得、Export、終了処理を通して確認する。
2. 暗室UI接続時に連続操作の要求集約、古いPreviewの破棄、操作応答性、長時間運用時の挙動を確認する。
3. 操作応答性が不足する場合、Session＋StageCacheを使うRust Adapterとの比較を検討する。今回のPoCではRust Adapterを試していない。
4. merge境界値、crop、カーブ、WB scale、Process V1／V2、RGB／RGBA Export、XMP交換など、実機PoCで扱っていない基本動作を必要に応じて確認する。
5. RAWプロファイルや現像アルゴリズムによる旧版との差は許容し、過去の編集結果との互換性は保証しない。必要なら編集結果を破棄して再現像する。

未確認事項はGenzoRoomからのMCP実接続、暗室UIの操作応答性、要求集約・古いPreviewの破棄、Session＋StageCacheを使うRust Adapterとの性能比較、process再起動をまたぐ設定復元、他のRAWや編集設定での挙動、GPU総VRAM peak、必要なライセンスレビューである。GPU実機PoCで確認した2素材の動作は全入力・設定の品質保証を意味しない。旧版との厳密な画像一致は確認対象としない。過去のv0.9.1実測は旧版PoC実績として保持し、v0.10.0での実行結果と区別する。
