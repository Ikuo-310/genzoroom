## Patch review

The previous patch passed `git apply --check` against clean v0.18.1 without rejects. All 29 managed targets remain; no patch feature was retired. `0002-v0.18.1-native-contracts.patch` is regenerated with full indexes and the new upstream context, rather than reusing obsolete blob identities. The previous patch and `versions/0.18.0.json` retain the old tuple for reproducibility.

A focused run reproduced its failure after v0.18.1 began constraining lens output even when Constrain Crop is off. Production geometry is not reverted to satisfy old pixel expectations.

## Upstream behavior and compatibility

`crop_drag.rs` is unchanged. Crop commands, aspect lock/presets, Straighten, orientation, flips and Crop Reset retain their contracts. The geometry path remains user orientation → lens/perspective warp → Crop/Straighten → output flips, sampled once. The Crop editing display continues to ignore canonical rectangle/angle for rendering while retaining orientation/flips and reporting canonical settings. The Frontend provisional Move/Resize calculations are unchanged.

`Frame::with_lens` now constrains output whenever `apply_crop=true`: lens/profile/manual distortion and all lateral CA planes are kept within the source independently of `geometry.constrain_crop`. Perspective participates only when that flag is enabled. Automatically estimated CA triggers the same constraint after estimation in `frame_for`. The centered shrink modifies the render Frame, not `DevelopSettings.crop`; uncropped editing (`apply_crop=false`) skips it. Cropped output dimensions and geometry IDs may therefore intentionally differ from v0.18.0 for the same optics settings. No cross-version pixel identity is required.

Whole metadata, Region planning/rendering and GPU rendering continue to use the effective Native Frame; Export uses the same pipeline framing. Crop edit and normal Whole keep separate geometry/mode identities. Existing stage-cache keys include settings and source identity. Upstream adds database-lens identity to source/view/thumbnail keys, rejects stale decodes after lens refresh, pins the catalog database profile over later decoder lookups, and raises render cache version 72→74.

Headless MCP and CLI file sessions now read an already downloaded system lens database, matching upstream Desktop behavior. They do not download it automatically. Profile availability can intentionally change corrected output; GenzoRoom adds no profile selection or lens controls.

`DevelopSettings` keeps serde defaults/unknown-field handling. `EmbeddedLens.source` defaults to file provenance and is omitted when file-derived. Legacy masks missing `on_photo` deserialize as false (old transformed-frame coordinates); newly created masks default true and follow source content through warps. Mask mapping gains inverse-warp support; GPU shapes requiring nonlinear coordinates use CPU evaluation. GenzoRoom does not publish mask editing. Existing settings normalization preserves Native readback; no schema/version change is needed.

RAW changes include Canon CRW support/calibration, Sony lens metadata and spectral/sparse decode changes, and bounded opcode work. These remain upstream decoding behavior. CLI calibration traversal is bounded; MCP/GenzoRoom tool names and response contracts are preserved.
